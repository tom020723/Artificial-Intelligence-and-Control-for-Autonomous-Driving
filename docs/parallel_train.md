# Phase 1 병렬 학습

프로젝트 루트에서 SUMO와 `libsumo`를 사용할 수 있는 Python 환경으로 실행한다. 현재 병렬 환경은 모든 신호가 청신호이고 배경 차량이 없는 Phase 1 설정을 사용한다.

```bash
python train_parallel.py --phase 1
```

`--phase`의 기본값은 `1`이며, 현재 지원하는 단계는 Phase 1이다. [도로 설정](../env/road_config.py)의 `ROUTE_ONLY_EXPERIMENT`를 `True`로 둔다.

기본값은 도로 **1,024개**(`--num-envs`), 차량당 **32 step**(`--steps-per-env`), PPO **100 iterations**(`--iterations`), 미니배치 **1,024**(`--minibatch-size`)다. Iteration당 32,768 step, 전체 3,276,800 step을 수집하며 무작위 가중치에서 시작한다. Iteration당 수집량은 미니배치 크기의 배수여야 한다.

## 구현 방식

- [도로 설정](../env/road_config.py)으로 [원본 도로](../env/road_builder.py)를 만들고, [병렬 환경](../env/parallel_sumo.py)이 서로 연결되지 않은 도로 복제본을 **SUMO 인스턴스 하나**에 넣는다. 도로당 ego 한 대를 두어 차량 간 간섭을 없앤다.
- 모든 ego에 같은 PPO 정책으로 계산한 행동을 적용한 뒤 SUMO를 한 step 진행한다. 관측·보상·종료 판정은 [기존 환경](../env/sumo_env.py)을 재사용하고, 에피소드가 끝난 차량만 재투입한다.
- 한 iteration은 rollout 수집과 PPO 학습으로 구성된다. [병렬 PPO](../algorithms/parallel_ppo.py)는 차량마다 GAE를 계산한 뒤 경험을 합쳐 학습한다.
- 정기 평가는 기본 **10 iterations마다** 실행한다. 별도 SUMO 프로세스에서 각 복제 도로를 결정적 정책으로 한 번씩 주행해 기본 **1,024개 에피소드**를 집계한다. 매번 같은 평가 seed를 사용한다. 간격은 `--eval-interval`로 바꿀 수 있고, `0`이면 정기 평가를 끈다.

기본 장치 설정에서는 CUDA를 사용할 수 있으면 정책 추론과 PPO 학습을 GPU에서 실행한다. SUMO 시뮬레이션과 관측·보상 계산은 CPU에서 수행한다.

결과는 `results/parallel_<phase>_<시간>/`에 저장된다. `parallel_config.json`에서 환경 수 등 실행 설정을, `training_log.csv`와 `eval_log.csv`에서 학습·평가 기록을 확인할 수 있다. 최종 가중치는 `model.pt`이며, 생성한 복제 도로 파일은 `parallel/`에 들어간다.

# Phase 2 병렬 학습 (신호등 작동, 배경 차량 없음)

## 한눈에 보기

**결과:** 256개 경로 평가에서 **도착 100%, 신호 위반 0%**. 빨간불에서 **정지선 약 5m 앞**에 선다 (이전: 13~45m 앞). seed 3개로 확인했다.

**바뀐 것 4가지**

| # | 무엇을 | 왜 | 파일 |
|---|---|---|---|
| ① | 교차로 내부 차선에서도 차선 관측을 정상적으로 계산 | 관측값이 튀어서, 정책이 그 지점을 "멈출 곳"으로 외웠다 | `env/sumo_env.py` |
| ② | **새 보상** `off_route_lane_penalty`: 경로 밖 차선에 있으면 매 스텝 감점 | 잘못된 차선에서 서서 기다려도 손해가 없었다 | `env/sumo_env.py`, `env/mdp_config.py` |
| ③ | 빨간불 정지 감점을 키움 (`red_stop_penalty_coef` 0.05→0.1, `red_stop_distance_scale` 100→50) | 감점이 너무 작아서 정지 위치가 학습마다 제멋대로였다 | 실행 옵션만 (코드 변경 없음) |
| ④ | 병렬 SUMO에서 순간이동(teleport) 끔 | 오래 멈춘 차가 순간이동하면 "신호 위반"으로 잘못 기록됐다 | `env/parallel_sumo.py` |

**팀원이 알아야 할 것**

- ①은 관측 값의 의미를 바꾼다. **이전에 학습한 모델(Phase 1 포함)은 이 코드에서 예전처럼 동작하지 않을 수 있다.** 관측 크기(49차원)는 그대로다.
- ②의 기본값은 0(꺼짐)이다. 켜지 않으면 기존 학습 결과에 영향이 없다.
- Phase 2는 **Phase 1 모델에서 이어 학습하지 말고 처음부터** 학습한다. 이어 학습하면 브레이크를 못 배운다(아래 부록 A).
- 학습량은 **400만 step**을 권장한다. 200만 step으로는 seed에 따라 실패한다.

## 실행 방법

```bash
# 학습 (약 35~40분, CPU 8코어 기준)
python train_parallel.py --phase 2 --num-envs 256 --steps-per-env 64 --iterations 244 \
    --minibatch-size 512 --eval-interval 0 \
    --set reward.off_route_lane_penalty=0.05 \
    --set reward.red_stop_penalty_coef=0.1 \
    --set reward.red_stop_distance_scale=50

# 평가 (256개 경로, 무작위성 없이)
python scripts/evaluate_parallel.py results/parallel_2_<시간>

# GUI로 보기 (창이 뜨면 ▶ 클릭)
python test.py results/parallel_2_<시간>/model.pt --saved-config --episodes 3
```

**새로 생긴 옵션**

| 옵션 | 하는 일 |
|---|---|
| `--phase 2` | 신호등을 켠다 (`road_config.py`의 `signal_plan` 그대로). 복제 도로마다 신호 주기 시작 시점이 달라서, 한 번에 초록·노랑·빨강이 고루 섞인다. |
| `--set 그룹.키=값` | 파일을 고치지 않고 설정을 바꾼다. 그룹은 `reward`, `hparams`, `obs`. 바꾼 값은 결과 폴더의 `parallel_config.json`에 남는다. 예: seed 변경은 `--set hparams.seed=1` |
| `--signal-green MIN MAX` | 도로마다 초록불 길이를 무작위로 정한다. 평가 스크립트에도 같은 옵션이 있어서, 학습 때 못 본 신호 길이로 시험할 수 있다. |
| `--init-model 경로` | 저장된 모델에서 이어 학습한다. |
| `--checkpoint-interval N` | N iteration마다 중간 모델을 저장한다. |
| `--name 이름` | 결과 폴더 이름 뒤에 실험 이름을 붙인다. |

`scripts/evaluate_parallel.py`는 도착률 외에 **빨간불 정지 거리**(멈춰 있는 동안 정지선까지 거리)와 **재출발 지연**(초록불 후 다시 출발까지 걸린 시간)도 출력한다.

관측은 `docs/train.md`의 49차원(목적지 one-hot 제외, 신호 1개)에 맞췄다. 저장소의 이전 기본값은 59차원이었다. 그래서 `tests/test_lookahead_connectivity.py`의 테스트 6개가 59차원을 기대하다 실패한다. 이번 수정과는 무관하다.

## 무엇이 문제였고 어떻게 고쳤나

처음 문제는 하나였다. **빨간불에서 정지선보다 13~45m 앞에 멈춘다.** 접근 도로마다 멈추는 거리가 일정했다(A1 26m, A2 13m, A3 37m, A4 40m, A5 45m). 원인을 따라가 보니 아래 4가지가 겹쳐 있었다.

### ① 교차로 내부 차선에서 관측이 튐

**증상:** A1 차량을 한 스텝씩 추적한 결과.

| 차량 위치 | 정지선까지 | 가속 출력 |
|---|---:|---:|
| 일반 도로 | 34m | -0.11 (살짝 감속) |
| **내부 차선 진입** | 30m | **-0.86 (급제동)** |
| 내부 차선에서 정지 | 24.5m | -0.88 |

정지선 거리는 매끄럽게 줄어드는데, 내부 차선에 들어가는 순간에만 급제동한다. SUMO 자동 제동은 꺼져 있으므로(`speedMode 0`) 정책 스스로 한 행동이다.

**원인:** 노드 안의 짧은 연결 차선(`:nM_A1_0_4_2` 같은 내부 차선)에서는 관측 코드가 차선 정보를 계산하지 않고 고정값을 넣었다.

- 차선 연결성 9개 → 전부 1 ("모든 차선이 있고 이어진다". 실제로 없는 차선까지 포함)
- 차선 밀도 5개 → 전부 0

일반 도로에서는 나올 수 없는 입력이라, 정책이 "이 입력 + 빨간불 = 멈춰라"로 외웠다. 내부 차선은 접근 도로마다 위치가 고정이라 멈추는 거리도 도로마다 일정했다.

**수정:** `_reference_lane()`을 추가했다. 내부 차선에 있을 때는 **그 차선이 이어지는 다음 일반 차선**을 기준으로 계산한다. 위치는 "다음 차선 시작점까지 남은 거리만큼 뒤"로 둔다. 이제 내부 차선을 지날 때도 값이 앞뒤 도로와 끊김 없이 이어진다(예: 0.58 → 0.46). 차선 연결성, 밀도, lookahead 연결성 세 관측에 모두 적용했다.

### ② 잘못된 차선에서 서서 기다려도 손해가 없음

**증상:** ①을 고친 뒤 도착률이 99.6%에서 89.5%로 떨어졌다. 실패는 A4→A2, A5→A3, A5→A5 세 경로에 몰려 있었다. 추적해 보니 이랬다.

1. 경로상 2번 차선으로 가야 하는데 1번 차선에 있다.
2. "차선이 끝난다"는 관측을 보고 **초록불인데도** 정지선 9m 앞에 멈춘다.
3. 차선을 바꾸지 않고 초록불을 몇 번이나 그냥 보낸다.

**원인:** 경로로 이어지지 않는 차선에서는 **차선 끝 5m 이내**에 서야만 감점·종료된다. 그보다 뒤에 서 있으면 아무 감점이 없다. 서 있는 시간 비용도 없고, 차선 변경에는 오히려 감점(-0.02)이 있다. 그래서 정책은 "서서 우연히 차선이 바뀌길 기다리기"를 배웠다.

- 학습 중에는 행동을 무작위로 뽑으므로 가끔(스텝당 1~3%) 차선이 바뀌어 빠져나온다.
- 평가(무작위성 없음)에서는 영원히 서 있는다.

같은 모델을 **차선 변경만 무작위로 뽑게** 해서 평가하면 도착률이 89.5%에서 98.4%로 오른다. 정책이 망가진 게 아니라, 확실하게 차선을 바꾸는 법을 못 배운 것이다.

**수정:** 새 보상 `off_route_lane_penalty`. 경로로 이어지지 않는 차선에 있고, 그 차선 끝이 시야(50m) 안에 들어온 동안 **매 스텝 감점**한다. 차선을 바꾸는 순간 감점이 멈추므로 "지금 바꾸는 게 이득"이라는 신호가 바로 생긴다. `blocked_penalty`(느린 앞차에 막혔을 때 감점)와 같은 방식이다. 권장값 0.05, 기본값 0(꺼짐).

### ③ 정지 위치를 정해 주는 보상이 너무 약함

**증상:** ①②를 고쳐도 정지 거리가 학습마다 크게 달랐다(24m → 12m → 33m).

**원인:** 빨간불 정지 감점(`red_stop_penalty`)은 정지선까지 남은 거리에 비례한다. 그런데 기존 값(`coef=0.05`, `scale=100`)에서는 30m 앞에 서도 **스텝당 0.013**이다. 사실상 0이라 정책은 "안전한 아무 데나" 선다.

**수정:** 실행 옵션으로 감점을 키웠다. 코드는 그대로다.

| 설정 | 30m 앞에 설 때 | 12m 앞에 설 때 | 결과 |
|---|---:|---:|---|
| 기존 (`coef 0.05`, `scale 100`) | 0.013 | 0.005 | 정지 위치가 제멋대로 |
| **권장 (`coef 0.1`, `scale 50`)** | 0.054 | 0.018 | **정지선 약 5m 앞** |
| 너무 셈 (`coef 0.2`, `scale 50`) | 0.108 | 0.036 | 학습 붕괴 (도착 55%) |

감점은 정지선 3m 앞(`red_stop_margin`)에서 0이 된다. 이전에 시도한 `scale=20`은 23m보다 멀면 감점이 상한에 붙어서, 다가갈수록 감점이 줄어드는 기울기가 없었다. 효과가 없었던 이유다.

### ④ 순간이동이 신호 위반으로 기록됨

**증상:** ②의 갇힌 차들이 "신호 위반"으로 기록됐다. 위반 순간 차는 이미 300초 넘게 서 있었다.

**원인:** SUMO는 기본적으로 300초 넘게 멈춘 차를 다른 곳으로 순간이동시킨다. 그러면 이동 거리가 갑자기 늘어서, 신호 위반 판정 코드가 "정지선을 넘었다"고 판단한다.

**수정:** 병렬 환경에서 `--time-to-teleport -1`로 순간이동을 껐다. 이제 갇힌 차는 "시간 초과"로 기록된다. 단일 환경(`sumo_env.py`)의 SUMO 옵션은 바꾸지 않았다.

## 결과

모두 256개 경로, 무작위성 없는 평가, 고정 신호(초록 20초, 주기 125초). 정지 거리는 빨간불에 멈춰 있는 동안 정지선까지의 거리다.

### 하나씩 적용했을 때 (seed 0, 200만 step)

| 적용한 수정 | 도착 | 신호 위반 | 잘못된 차선 | 정지 거리 (중간값 / 먼 쪽 10%) |
|---|---:|---:|---:|---:|
| 수정 전 | 99.6% | 0.4% | 0% | 24m / 39m |
| + ① 관측 수정 | 89.5% | 10.5% ※ | 0% | 12m / 22m |
| + ② 경로 밖 차선 감점 (+④) | 100% | 0% | 0% | 33m / 48m |
| + ③ 정지 감점 강화 | **99.6%** | **0.4%** | **0%** | **5.8m / 8.1m** |

※ 대부분 ②의 갇힌 차가 ④ 때문에 위반으로 잘못 기록된 것이다.

### seed별 재현성 (최종 설정)

| seed | 학습량 | 도착 | 신호 위반 | 잘못된 차선 | 정지 거리 (중간값 / 먼 쪽 10%) |
|---|---:|---:|---:|---:|---:|
| 0 | 200만 | 99.6% | 0.4% | 0% | 5.8m / 8.1m |
| 1 | 200만 | 61.3% | 9.8% | 28.9% | 28m / 64m |
| 1 | **400만** | **100%** | 0% | 0% | 10.4m / 20.4m |
| 2 | 200만 | 98.8% | 0.8% | 0.4% | 24m / 52m |
| 2 | **400만** | **100%** | 0% | 0% | **5.0m / 8.4m** |

- **200만 step은 seed에 따라 부족하다.** seed 1은 훈련 보상이 끝까지 5~6에 머물렀다. 400만 step이면 세 seed 모두 도착 99.6% 이상이다.
- seed 1은 400만 step에서도 정지 거리가 10m로, 다른 seed보다 덜 다듬어졌다.

## 한계

- 400만 step 결과는 200만 step 모델을 `--init-model`로 200만 step 더 이어 학습한 것이다. 위 실행 방법의 명령(244 iterations 한 번에)을 그대로 돌려 본 적은 아직 없다.
- 배경 차량이 없는 조건이다. Phase 3에서는 앞차 뒤에 줄을 서야 하므로 정지 위치 감점이 다르게 작용할 수 있다.
- `env/parallel_sumo.py`는 아직 배경 차량을 지원하지 않는다(`_ReplicaEgo._neighbor`가 항상 `None`).

## 부록 A. Phase 1 모델에서 이어 학습하면 안 되는 이유

수정 ①~④ 이전 코드, seed 0, 256개 경로 평가.

| 시작 가중치 | 학습량 | 도착 | 신호 위반 | 잘못된 차선 |
|---|---:|---:|---:|---:|
| Phase 1 모델 그대로 | 0 | 55.1% | 38.7% | 6.3% |
| Phase 1 모델에서 이어 학습 | 98만 step | 54.7% | 5.1% | 40.2% |
| **처음부터 학습** | 200만 step | **99.6%** | 0.4% | 0% |

Phase 1 모델은 가속 출력이 최대값에 붙어 있어서(항상 초록불이었으므로), 이어 학습해도 브레이크를 배우지 못했다. 처음부터 학습한 모델은 학습 때 못 본 신호 길이(초록 5~40초 무작위)에서도 256/256 도착했다.

## 부록 B. 효과가 없었던 시도

수정 ①~④ 이전, 각 1회 실험: 초기 탐험 폭 축소(`init_log_std=-1.0`), `gamma=0.995`, `wrong_lane_penalty=5`, `red_stop_distance_scale=20`(이유는 ③ 참고), 빨간불 정지 감점 삭제, 정지선 미세 거리·제동 요구량 관측 추가.
