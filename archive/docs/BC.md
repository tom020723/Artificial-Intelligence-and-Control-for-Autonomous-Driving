# 행동 복제(BC) 기준 코드

현재 기준은 **실제 범퍼 사이 거리를 포함한 49차원 관측으로 SUMO 전문가의 가감속과 차선변경을 학습하는 정책**이다. 비교 대상은 BC 브랜치의 이전 커밋 `fae3f3f`(Phase 1 기준 코드)다.

## 이전 커밋 대비 변경점

| 항목 | 이전 커밋 `fae3f3f` | 현재 BC 기준 |
|---|---|---|
| 학습 | Phase 1 PPO 학습 및 평가 | SUMO 전문가의 행동을 지도학습하고 PPO와 같은 hybrid actor 형식으로 저장 |
| 주변 차량 | 현재 차선과 좌우 2개 차선의 앞·뒤 차량. 거리의 기준이 조회 방식에 따라 달랐음 | 같은 5개 차선의 앞·뒤 차량을 실제 범퍼 사이 거리로 통일. 가까운 차량도 관측을 유지 |
| 차선 연결성 | 좌우 4개 차선의 연결성, 향후 경로의 차선 연결성, 목적지 one-hot | 좌우 2개 차선의 물리적 연결성, 다음 두 도로 분기의 경로 안내 |
| 신호 | 전방 신호 최대 2개의 상태와 거리 | 가장 가까운 전방 제어 신호 1개의 상태와 실제 정지선 거리 |
| 링 합류 | 별도 관측 없음 | 링 구간 여부, 합류점까지 거리, 상대 접근 차량 최대 2대 |
| 전문가 수집 | Phase 1 학습이 기준 | 3,000대/시간에서 차선 수에 비례해 배경교통을 투입하고, 독립 회차별 관측·행동을 저장 |
| 충돌 판정 | SUMO 차량 타입별 기본 충돌 기준 | 자차와 배경차 모두 범퍼 간 0.2m를 기준으로 수집·평가. 추종 모델의 `minGap`은 별도 설정 |
| 평가 | Phase 1 기준 평가 | 0·1,000·2,000·3,000대/시간별 경로·신호 조합을 평가하고 완주·충돌·신호 위반·차선 실패를 집계 |

## 관측 49차원

인덱스는 0부터 시작한다. 차선별 블록 순서는 **좌2, 좌1, 현재, 우1, 우2**다. 속도 정규화에는 도로 제한속도 `vmax`를 사용한다.

| 인덱스 | 차원 | 입력 |
|---|---:|---|
| 0 | 1 | 자차 속도 / `vmax` |
| 1–20 | 20 | 차선마다 `[앞차 거리/50, 앞차 상대속도/vmax, -뒤차 거리/50, 뒤차 상대속도/vmax]` |
| 21–25 | 5 | 같은 5개 차선의 물리적 연결성 |
| 26–30 | 5 | 같은 5개 차선의 전방 차량 밀도 |
| 31–34 | 4 | `[적색, 황색, 녹색, 정지선까지 거리/200]` |
| 35–38 | 4 | 다음 도로 분기 `[유효 여부, 거리/650, sin(각도), cos(각도)]` |
| 39–42 | 4 | 두 번째 도로 분기. 첫 번째와 같은 형식 |
| 43–48 | 6 | `[링 여부, 자차의 합류점까지 거리/50, 차량 1 속도/vmax, 차량 1의 합류점까지 거리/50, 차량 2 속도/vmax, 차량 2의 합류점까지 거리/50]` |

- **주변 차량**은 50m 범위의 실제 범퍼 사이 거리를 사용한다. 물리적으로 겹친 경우 거리는 0으로 제한하고 상대속도는 유지한다. 상대속도는 상대 차량 속도에서 자차 속도를 뺀 값이다. 앞차가 없으면 `[1, 1]`, 뒤차가 없으면 `[-1, -1]`이다.
- **차선 연결성**은 없는 차선 `-1`, 이어지는 차선 `1`, 50m 이내에서 끝나는 차선은 남은 거리/50이다. 어느 도로로든 연결되는지를 나타내는 물리 정보이며, 예정 경로에 맞는 차선을 지정하지 않는다.
- **차선 밀도**는 전방의 차량 수를 해당 구간의 수용 대수(사용 가능한 거리 / 7.5m)로 나눈 값이다. 사용 가능한 거리는 최대 50m이며 연결이 끊긴 차선은 끝까지만 센다. 값은 0~1이며 없는 차선에는 1을 준다.
- **신호**는 전방 100m 이내에서 가장 가까운 제어 신호를 사용한다. 거리는 자차 앞범퍼에서 정지선까지 경로를 따라 잰다. 해당 신호가 없으면 네 값 모두 0이다.
- **경로 안내**는 도로가 갈라지는 선택 지점까지의 경로상 거리와 진출 도로 방향을 전달한다. 양의 각도는 왼쪽이다. 거리 650m는 정규화 기준이며 값은 자르지 않는다. 안내가 없으면 해당 네 값은 모두 0이다.
- **링 합류**는 링 위에서 합류 상대 차선의 차량 중 자차와 직선거리 50m 이내인 차량을, 각 차량의 합류점까지 남은 거리 순으로 최대 2대 선택한다. 빠진 차량 슬롯은 `[0, -1]`, 링 관측을 쓰지 않는 구간은 `[0, -1, 0, -1, 0, -1]`이다.

구현은 [공통 관측 환경](../env/sumo_env.py), [도로 단위 경로 안내](../env/route_guidance.py), [링 관측](../env/ring_observation.py)에 있다. 49차원이라도 기존 거리 인코딩으로 학습한 모델과 현재 범퍼 거리 입력은 의미가 다르다.

## 전문가 데이터 수집

1. 노형오거리 도로망에 배경 교통량을 총 **3,000대/시간**으로 설정한다. 시작 도로별 유입량은 진입 차선 수에 비례시키고, 각 도로의 경로 비중은 유지한다. 배경차 타입 비율은 Krauss 35%, IDM 30%, EIDM 20%, ACC 15%다. **ACC는 도로에서 주행하지만 전문가 표본은 Krauss·IDM·EIDM에서만 수집한다.**
2. 회차마다 독립 seed로 SUMO를 시작하고, **250초 + seed별 0~119초** 동안 교통을 채운 뒤 **180초**를 수집한다. 수집 주기는 **0.5초**다. SUMO가 배경차의 추종과 차선변경을 제어한다. 경로를 따르기 위한 변경과 속도 이득을 위한 변경을 허용하며, 첫 출발 도로의 처음 30m와 내부 연결로에서는 차선변경을 제한한다.
3. 각 전문가 차량에 대해 스텝 시작 시 위의 49차원 관측을 만들고, 스텝 종료 후 실제 행동과 짝을 맞춘다. 가감속 정답은 `(다음 속도 - 현재 속도) / 0.5초`를 자차의 최대 가속 또는 최대 감속으로 나눈 값이다. 차선변경 정답은 SUMO 이벤트에서 읽으며 `+1`은 왼쪽, `0`은 유지, `-1`은 오른쪽이다. 도로가 바뀌며 차선 번호만 달라지는 경우는 차선변경으로 세지 않는다.
4. 충돌 또는 텔레포트로 표시된 차량의 해당 회차 표본을 제외한다. 다음 스텝 상태가 없거나 자차의 가감속·속도 한계를 초과하는 행동도 제외한다. 자차와 모든 배경차에 물리적 충돌 기준 **0.2m**를 적용하며 각 차량의 추종 `minGap`은 유지한다.
5. 회차마다 `episode_*.npz`에 관측, 행동 정답, 차량 종류와 ID, 시각, 경로 등을 저장한다. `manifest.json`은 회차 파일과 유효 표본 수를 기록하고 `config.json`은 수집 설정을 기록한다. 목표는 **ACC 제외 유효 표본 1억 1,000만 건**이며, 완료된 회차까지 포함하므로 최종 건수는 목표보다 조금 클 수 있다.

기준 데이터 수집에는 독립 SUMO 워커 4개를 사용했다. **현재 수집 기본값은 12워커**다. 워커마다 독립적인 SUMO를 실행하고 회차 번호로 고유 seed와 출력 파일을 정한다. 최종 manifest는 완료된 회차를 seed 순서로 기록한다. 수집기와 전체 파이프라인에서 `--num-workers`로 워커 수를 조정할 수 있다.

## 학습과 평가

- **학습**은 수집 회차 단위로 약 80%를 학습, 20%를 검증에 사용한다. 입력 정규화 통계는 학습 회차에서 계산한다. seed 0에서 **49→256→256 hybrid actor**를 새로 초기화하고, 가감속 MSE와 차선변경 빈도의 역제곱근을 가중치로 사용한 교차 엔트로피를 합해 학습한다. Adam, 배치 4,096, 학습률 0.0003, 100 epoch를 사용한다. 검증 손실이 가장 낮은 모델은 `model.pt`다. 내보낼 때 입력 정규화를 첫 선형 계층에 합쳐 PPO와 같은 형식으로 저장한다.
- **평가**는 가감속과 차선변경을 결정적으로 출력한다. **0·1,000·2,000·3,000대/시간**, 각각 **23개 경로 × 50개 신호 시작 시점**으로 총 4,600회를 평가한다. 유교통 조건은 배경차를 250초 동안 먼저 운행한 뒤 요청한 신호 시점에 맞는 교통 상태를 불러와 자차를 투입한다. 평가 워커는 4개다. 완주, 충돌, 신호 위반, 차선 실패를 집계한다.

저장소 루트에서 SUMO와 학습 의존성이 설치된 환경으로 아래 명령을 실행한다. `--layout bc49`는 위 표의 49차원 관측을 선택하는 CLI 옵션이다. 이 실행에 필요한 범퍼 거리 모드와 차량별 충돌 기준은 각각 `env/mdp_config.py`와 `env/road_config.py`에 설정되어 있다.

```bash
stamp=$(date +%Y%m%d_%H%M%S)
data_dir="data/background_expert_${stamp}"
run_dir="results/BC_${stamp}"

python collect_background_data.py --layout bc49 --sharded \
  --traffic-vph 3000 --origin-lane-proportional \
  --episodes 10000 --seed 99000 --warmup-seconds 250 --seconds 180 \
  --spawn-protect-m 30 --exclude-vehicle-type car_acc \
  --target-samples 110000000 --out-dir "$data_dir"

python scripts/check_bc_shards.py "$data_dir"

python scripts/train_bc_shards.py "$data_dir" --out-dir "$run_dir" \
  --epochs 100 --patience 100 --wall-seconds 21600 \
  --batch-size 8192 --lr 0.00042 --seed 0 --device cuda

python scripts/evaluate_quick_bc.py "$run_dir/model.pt" \
  --num-workers 4 --ego-collision-gap-m 0.2 --background-collision-gap-m 0.2 \
  --out-dir "$run_dir/analysis/bumper_full"
```

수집이 저장 공간이나 회차 제한으로 일찍 끝날 수 있으므로, 학습 전에 `manifest.json`의 `samples`가 목표에 도달했는지 확인한다. 위 수집·학습 명령에 명시한 설정은 현재 기본값이므로 필요할 때만 옵션을 바꾼다. 위 단계들을 한 번에 실행하려면 `python scripts/run_bc_bumper_full.py`를 사용한다. 이 스크립트는 목표 표본 수와 학습 epoch 수를 확인하고 평가까지 이어간다.

## 기준 모델 결과

전문가 표본 **110,007,415건**으로 학습했다. 검증 손실이 가장 낮은 **99 epoch** 체크포인트를 선택했고, 교통량마다 1,150회 평가했다.

| 교통량 (대/시간) | 완주율 | 충돌 | 신호 위반 | 차선 실패 |
|---:|---:|---:|---:|---:|
| 0 | 98.61% | 0 | 0 | 16 |
| 1,000 | 95.65% | 5 | 6 | 39 |
| 2,000 | 95.65% | 9 | 2 | 39 |
| 3,000 | 91.65% | 32 | 3 | 61 |

기준 실행의 로컬 모델 경로는 `results/bc49_bumper_noacc_full_seed0_20261118_140850/selected_model.pt`다. 평가 집계와 그래프는 같은 실행의 `analysis/bumper_full/`에 있다. BC 학습의 기본 저장 폴더는 `results/BC_YYYYMMDD_HHMMSS`다. 같은 초에 기본 경로가 겹치면 학습 스크립트가 `_2`부터 번호를 붙인다. `--out-dir`로 경로를 지정할 수 있다.
